# 真实环境联调验收清单

> **适用版本**：Minecraft Java 26.1.2 + Fabric + Carpet + Carpet-LMS-Addition **v1.15.0** + Chrome / Edge
> **谁来执行**：本清单需要你在自己的游戏机上执行。交付仓库里只有面板、安装器和纯标准库测试，
> 不含 MC / LMS / 存档 / 浏览器环境，也不含任何第三方文件；离线测试用合成 jar、gzip NBT 和 DOM 桩
> 验证过逻辑，但**不能代替真实服务端联调**。
> **网络**：整份清单只访问本机 `127.0.0.1`，不需要联网（局域网可达性检查除外，见 E 步）。

## 1. 安装与启动（保留完整命令输出）

1. **完全退出游戏**（回主菜单不算）——同一次游戏进程内切存档时，LMS v1.15.0 的网站目录是 `static final`，
   启动时按第一个加载的存档固定，之后 `/storageWebsite restart` 也不会变。
2. 解压本仓库，在解压目录打开终端，执行 `python install.py`，按提示选目标存档。
   - 记录：是否出现 `noPassword` 警告、安装完成提示、最终端口。
   - 预期：预检通过 → 从你的 LMS jar 提取网站 → 注入一行 `<script>` → 提示「安装完成!」。
3. 进入该存档，游戏内 `/storageWebsite start`（安装已开启 `autoStartWebsite`，以后重启会自动起）。
4. Chrome / Edge 打开 `http://127.0.0.1:7000`（端口以第 0.7 步为准），按 `Ctrl+F5` 强制刷新。
5. 右边缘出现橙色「⭐ 重要物品」按钮；按 F12 打开 DevTools，**Console 无红色报错**。

## 2. 四个重点验收点

### A. `config.json` 失败时面板保持锁定、不写 `_unknown`

> 这是两个阻断级修复之一，务必实机确认。建议在 DevTools → Network 勾上 **Preserve log** 再做。

**制造失败**（任选一种，做完记得恢复）：
- 简单法：DevTools → Network → 右键任意请求 → **Block request URL**，填 `*/config.json`，然后 `Ctrl+F5`；
- 或：把网站目录下的 `config.json` 临时改名，**只改一个测试存档**，验完立刻改回。

**预期结果**：
- 面板顶部提示「存档名读取失败，刷新页面重试」，主体灰化锁定；
- 「⭐ 重要物品」入口能打开，**关闭按钮 `#ipv-close` 仍可点**（不应被 `pointer-events:none` 连坐禁用）；
- 点「默认排序」等工具按钮无任何反应；Console 出现 `[重要物品] 读取 config.json ...` 的 warn。

**判定（关键）**：DevTools → **Application → Local Storage** → 逐个看键名，
**不应出现任何 `ipv.*._unknown` 结尾的键**；已有偏好也不应被覆盖。
数据层 `lsSet()` 守卫会在 `worldName` 为空时直接拒绝写入，即使 CSS 的 `pointer-events` 语义在浏览器间有差异也不会串档。

**恢复**：取消 Block / 改回文件名 → `Ctrl+F5` → 面板解锁、顶部显示「当前存档：xxx」、正常渲染 32 行。

**取证**：面板截图 + Console 文本 + localStorage 键名列表截图。

### B. 登录后取货的两步 API

> ⚠️ 这一步会**真的从仓库取走物品**，请用小数量（如 1），并提前确认仓库里有货。

1. 网站右上角用「游戏名 + 密码」登录（不登录只能看库存）。
2. 打开「⭐ 重要物品」→ 点某物品行的「取货」→ 输入 `1` → 确认框确认。
3. DevTools → Network 按时间顺序应看到**两条** POST，且都是 200：

| 顺序 | 接口 | 请求体 | 响应 / 作用 |
|---|---|---|---|
| 1 | `POST /api/storage/getItem` | `{ i: <物品id>, c: <数量> }`，带 `Authorization: Bearer <token>` | 返回假人数组 `[{ c, n }, ...]` |
| 2 | `POST /api/storage/sendGetItemResult` | 上一步的假人数组 `[{ i, c, n }, ...]` | 通知 LMS 交付完成 |

4. 预期：面板显示「取货成功！实际取走 N 个（按整格补齐）」；游戏聊天框出现 `[↑][↓][O]`。
5. 未登录时预期：提示「尚未登录」，**且 Network 里不出现 `getItem`**。
6. 收尾：点 `[↑]` 让假人上线、`[O]` 开背包取回，或游戏内 `/cleanGetItemBot clean 1000` 批量回收。

**取证**：两条请求的 Headers / Response 截图 —— **截图前把 `Authorization`、Cookie、token 打码**。

### D. 损坏 / 越界 jar 重装时保留原网站目录

> 这条已在仓库的纯标准库测试里用合成 jar 验证过（`tests/README.md` T4），实机复验是为了确认真实
> LMS 目录布局下的行为。**请只在测试实例 / 测试存档上做。**

1. 先把 `saves/<存档>/carpetlmsaddition/customStorageWebsite/` 整个**复制到别处**做备份。
2. 用一个损坏的、或含 `../` 越界条目的 jar 临时替换 `mods/` 里的 LMS jar，执行 `python install.py`。
3. 预期：安装器 **exit=1**，报「路径越界」或「jar 损坏」，且：
   - `customStorageWebsite/` 内容与第 1 步的备份**逐文件一致**；
   - 没有生成任何越界文件（如 `PWNED.txt`）；
   - 目录里不留 `.ipv-staging` / `.ipv-backup` / 半个网站。
4. 恢复：换回真实 jar，重跑 `python install.py` 并 `Ctrl+F5`。

**取证**：安装器完整 stdout + 目录对比结果。

### E. `noPassword=false` 与局域网暴露面（安全）

1. 打开 `saves/<存档>/carpetlmsaddition/checkStorageConfig.json`，确认 `noPassword` 为 `false`；
   顺便**只回答「有 / 无」**：该文件里是否出现密码或 hash 类字段（**不要记录或截图字段值**）。
2. 安装器输出里不应出现 `[!] 安全警告: noPassword=true`。
3. 从同一局域网的另一台设备访问 `http://<本机IP>:<端口>/`：**应被要求登录**，未登录不能下单取货。
4. 若第 3 步能直接取货 → 立即停止联调、设置密码、检查防火墙。

> 代码侧已覆盖：`install.py:563-565` 在 `noPassword=true` 时打印警告；`update_storage_config()` 只改
> `customWebsite` / `autoStartWebsite` / `port` / `storageList` 四项，**不会把 noPassword 改成 true**；
> 回归测试 `test_t8_existing_fields_preserved` 断言 `noPassword=False` 安装后保持不变。
> 本步要确认的是**真实 LMS v1.15.0 生成的默认取值**与实机访问控制。

## 3. 浏览器控制台只读自检（可粘贴）

> 在网站页面按 F12 → Console 粘贴整段回车。**只读**：不写 localStorage、不调用 `getItem` /
> `sendGetItemResult`、不触发取货、不改动任何偏好。唯一的网络请求是页面本来就会发的
> `/config.json` 和只读的 `/api/storage/getData`。

```js
(function () {
  'use strict';
  var out = [];
  function log(name, ok, detail) {
    out.push({ 检查: name, 结果: ok ? 'PASS' : 'CHECK', 详情: String(detail) });
  }
  var TOKEN_KEY = 'storageWebsite.authToken';

  fetch('/config.json', { cache: 'no-store' })
    .then(function (r) {
      return r.ok ? r.json().then(function (c) { return { s: r.status, c: c }; })
                  : { s: r.status, c: null };
    })
    .catch(function (e) { return { s: 'ERR', c: null, e: String(e) }; })
    .then(function (res) {
      log('/config.json 状态', res.s === 200, res.s + (res.e ? ' ' + res.e : ''));
      log('worldName 存在', !!(res.c && res.c.worldName),
          res.c && res.c.worldName ? res.c.worldName : '（空 / 缺失 → 面板应保持锁定）');

      // 1) 串档键检查：只读遍历，不写入
      var bad = [];
      for (var i = 0; i < localStorage.length; i++) {
        var k = localStorage.key(i);
        if (k.indexOf('ipv.') === 0 && k.indexOf('._unknown') !== -1) bad.push(k);
      }
      log('无 ipv.*._unknown 串档键', bad.length === 0, bad.length ? bad.join(', ') : '无');

      // 2) 锁定态与关闭按钮（验证 :not(#ipv-close) 没有连坐禁用）
      var panel = document.getElementById('ipv-panel');
      if (!panel) {
        log('面板已注入', false, '未找到 #ipv-panel，请 Ctrl+F5 强刷');
      } else {
        log('面板锁定态', true,
            panel.classList.contains('ipv-locked') ? 'ipv-locked（存档名未就绪）' : 'unlocked');
        var close = document.getElementById('ipv-close');
        if (close) {
          var pe = window.getComputedStyle(close).pointerEvents;
          log('关闭按钮可点', pe !== 'none', 'pointer-events=' + pe);
        } else {
          log('关闭按钮可点', false, '未找到 #ipv-close');
        }
      }
      log('已登录', !!localStorage.getItem(TOKEN_KEY),
          localStorage.getItem(TOKEN_KEY) ? '有 token（不要外传）' : '未登录，取货会提示「尚未登录」');

      // 3) 只读库存接口，与面板同样的 header；不下单
      var t = localStorage.getItem(TOKEN_KEY) || '';
      return fetch('/api/storage/getData', {
        headers: t ? { 'Authorization': 'Bearer ' + t } : {}, cache: 'no-store'
      }).then(function (r) { return r.ok ? r.json() : { __status: r.status }; })
        .catch(function (e) { return { __error: String(e) }; });
    })
    .then(function (data) {
      if (data === undefined) return;
      var ok = data && !data.__status && !data.__error;
      log('getData 可读', !!ok,
          ok ? '顶层键: ' + Object.keys(data).slice(0, 6).join(', ')
             : JSON.stringify(data).slice(0, 120));
    })
    .then(function () {
      console.table(out);
      console.log('[重要物品] 自检完成：全程只读，未触发取货、未写入任何偏好。');
    });
})();
```

**怎么读结果**：`PASS` 是符合预期；`CHECK` 需要结合场景判断（例如未登录时 `getData` 返回 401 属正常；
故意制造 404 时 `/config.json 状态` 显示 404、`worldName 存在` 为 CHECK 也正是 **A 步要的预期**）。

## 5. 失败时怎么取证（以及别外传什么）

建议收集：

- 安装器**完整 stdout**（含存档名、端口、报错阶段）；
- DevTools **Console 全量文本**、**Network HAR**；
- **Application → Local Storage 的键名列表**（值可打码）；
- 游戏内 `/storageWebsite status` 输出；
- `saves/<存档>/carpetlmsaddition/checkStorageConfig.json` 的**键名**（不要值）。

> ⚠️ 提交 issue 或发到公开渠道前，务必删除：`Authorization` / Cookie /
> `storageWebsite.authToken` 的值、密码与 hash 字段值、局域网 IP、玩家名。
> 导出的 HAR 默认包含完整请求头，是最容易误泄 token 的一项。
